# 博客维护指南

网站：https://starlitvale.github.io/

源码：https://github.com/Starlitvale/starlitvale.github.io

部署状态：https://github.com/Starlitvale/starlitvale.github.io/actions

## 日常只需要做这几件事

桌面“个人博客”文件夹里的操作入口：

1. 双击 **新建文章.cmd**，输入标题和可选的英文文件名，会用 Windows 默认的 Markdown 编辑器打开新建的 `.md` 草稿；当前电脑已关联 Typora。
2. 写作、保存。双击 **本地预览.cmd** 可查看效果；预览窗口保持开启，改完保存会自动刷新。关闭命令窗口即可停止预览。
3. 准备公开时，把文章开头的 `draft: true` 改为 `draft: false`。
4. 双击 **发布博客.cmd**。它会先检查和构建，成功后提交并推送，再由 GitHub Actions 部署。通常需要几分钟；Actions 显示绿色后即可访问网站。

本地开发预览会显示草稿，搜索使用模板的演示结果。正式网站的搜索由 Pagefind 在构建后生成。

**GitHub 仓库是公开的。** `draft: true` 只会让文章不出现在生成的网站、RSS 与搜索中；一键发布会提交全部未忽略的源码，草稿内容仍然可在公开仓库中看到。私密笔记请保存在 `blog` 文件夹之外。

## 文章放在哪里

文章在 `src/content/posts/`，使用 Markdown 格式。以 `my-post.md` 为例，发布后的地址是 `/posts/my-post/`。发布后尽量不要修改文件名，否则原来的链接会变化。

```yaml
---
title: "我的第一篇文章"
published: 2026-10-29
description: "在首页显示的一句话摘要"
image: ""
tags: ["学习", "记录"]
category: "随笔"
draft: false
lang: ""
---
```

正文从第二条 `---` 后开始。修改旧文章时可加 `updated: 2026-10-30`。日期应填写真实的发布或更新时间；未来日期不会自动定时发布。

两条 `---` 之间是文章信息（Frontmatter），不属于正文：

| 字段 | 用途与填写方法 |
| --- | --- |
| `title` | 文章标题，显示在首页和文章页 |
| `published` | 发布日期，格式为 `年-月-日`，也用于文章排序 |
| `description` | 首页摘要与网页描述；留空时首页自动提取正文摘要 |
| `image` | 文章封面路径，例如 `/images/coffee.jpg`；留空则没有封面 |
| `tags` | 多个标签，例如 `["学习", "记录"]` |
| `category` | 文章分类，例如 `"随笔"`；一篇文章填写一个分类 |
| `draft` | `true` 为草稿，不生成到正式网站；`false` 才会生成到正式网站，仍需运行发布入口 |
| `lang` | 文章语言代码，不会显示为页面栏目，也不会翻译正文或切换网站菜单。留空或删除这一行会沿用网站中文；也可填 `zh_CN`（中文）或 `en`（英文） |
| `typora-copy-images-to` | Typora 插图时复制图片的位置。新文章自动填写为文章旁的 `.assets` 文件夹；保留这一项即可，不会显示在网页上 |

文章始终是 `.md` 文件。记事本、Typora、VS Code 都可以编辑同一个文件，使用哪个软件不会改变文件格式。当前电脑可直接双击 `src/content/posts/` 里的 `.md` 文件，用 Typora 写作并按 `Ctrl+S` 保存；不需要另存或导出为 `.txt`，也不需要先导出 HTML。

## 插入图片

### 在 Typora 中拖入或粘贴图片

Markdown 保存的是图片的引用路径，图片文件本身也必须保存在博客文件夹内，才能一起发布。`C:\Users\...`、`D:\...` 或 `file:///...` 这样的电脑路径无法在正式网站上显示。

新建文章已包含 Typora 的图片保存位置。例如 `my-post.md` 的开头会有：

```yaml
typora-copy-images-to: "./my-post.assets"
```

在 Typora 的“偏好设置 → 图像”中启用允许复制图片到指定文件夹（如果有这个选项），并勾选“优先使用相对路径”和“插入时自动转义图片 URL”（不同版本的名称可能略有差异）。保留文章开头的 `typora-copy-images-to` 设置，拖入或粘贴图片时，Typora 会按照文章设置把图片复制到旁边的 `my-post.assets/` 文件夹，并生成类似下面的内容：

```markdown
![咖啡](./my-post.assets/coffee.jpg)
```

**文件名有空格时，还要处理 Markdown 写法。** Typora 能显示未转义的带空格路径，但网页端的 Markdown 解析器不会把它识别成图片。启用上面的自动转义选项后，空格会写成 `%20`；已经插入的图片可以给整个路径加上英文尖括号 `< >`，例如：

```markdown
![截图](<./my-post.assets/屏幕截图 2026-10-29.png>)
```

中文文件名本身可以使用；也可以取 `screenshot-2026-10-29.png` 这样的无空格文件名。改名时要同步修改文章里的路径。

如果仍生成电脑绝对路径，可右键图片，选择“复制图片到…”并选取文章旁的 `.assets` 文件夹，再把链接改成上面的相对路径。旧文章可以在开头手动添加对应的 `typora-copy-images-to` 设置。Typora 操作说明：https://support.typora.io/Images/

只改这一行设置不会自动搬走之前插入的图片；已有图片仍需复制并更新引用。文章与 `.assets` 文件夹要一起保留、一起提交，发布入口会一并处理。文章仍为 `draft: true` 时，只有本地开发预览会显示。

### 手动使用公共图片

也可以把图片放到 `public/images/`（可自行创建），例如 `public/images/coffee.jpg`。正文写：

```markdown
![咖啡](/images/coffee.jpg)
```

如需文章封面，把开头的 `image` 填为 `/images/coffee.jpg`。上传前压缩大图有助于加快访问。

## 修改名称、署名与外观

统一编辑 `src/config.ts`：

| 位置 | 用途 |
| --- | --- |
| `siteConfig.title` | 博客名称，目前临时使用“个人博客” |
| `siteConfig.subtitle` | 一句话简介 |
| `siteConfig.themeColor.hue` | 默认主题色，范围 0–360 |
| `siteConfig.banner.enable` | 是否显示首页横幅 |
| `siteConfig.banner.src` | 横幅图片，使用自有图片时可填 `/images/banner.jpg` |
| `profileConfig.name` | 作者署名，目前使用 Starlitvale |
| `profileConfig.bio` | 侧栏简介 |
| `profileConfig.avatar` | 头像，目前是本地保存的 GitHub 头像 `/avatar.png` |
| `profileConfig.links` | 社交链接 |

“关于”页面是 `src/content/spec/about.md`。首页目前有一篇可修改或删除的开站示例 `hello-world.md`，没有虚构个人经历。

Fuwari 原始演示文章已放到 `docs/examples/`，可参考 Markdown、代码块、提示框等写法，不会作为文章发布。模板自带示例图片的来源见 `docs/图片来源.md`。

文章许可块暂未开启，页脚保留版权所有。需要明确采用 CC 等许可时，再调整 `licenseConfig`。

## 一键发布失败怎么办

- **检查/构建失败**：看命令窗口中的文章路径与错误行，通常是 YAML 引号、日期或图片路径有误；修好后重试。
- **推送失败**：修改已保存在本机。如果 GitHub 登录过期，按 Git 的提示重新登录；如果在网页端改过文章而导致分支不同步，把报错交给助手处理，避免强制推送。
- **推送成功但网页没变化**：查看 Actions，等部署完成后刷新。浏览器可能缓存旧页面。
- **Actions 红色**：打开失败任务的日志，交给助手修复。

## 换电脑或恢复

安装 Node.js 24 LTS 和 Git，登录 GitHub，然后：

```powershell
git clone https://github.com/Starlitvale/starlitvale.github.io.git blog
cd blog
npx --yes pnpm@9.14.4 install --frozen-lockfile
npx --yes pnpm@9.14.4 dev
```

发布命令是 `node scripts/publish.mjs`。源码和图片会由 GitHub 保存；请在完成写作后及时发布/备份，本机未提交的修改不会自动备份。

## 低频维护

GitHub 用户名改动会改变默认网站地址。账号现在是 `Starlitvale`，用户主页仓库须对应 `starlitvale.github.io`。以后如果再次修改用户名，需要同时更新仓库名、Git 远程地址、`astro.config.mjs`、`src/config.ts`、`scripts/publish.mjs` 与桌面的“打开博客.cmd”，再重新部署；旧的 `monitor666.github.io` 和 `asterford.github.io` 地址不会自动重定向到新博客。

日常发文无需更新依赖。依赖和模板升级可交给助手，升级后须通过 `pnpm check` 和 `pnpm build` 再发布。GitHub 免费地址已可用；以后如果需要自定义域名，再单独配置 DNS、`astro.config.mjs`、RSS 链接和 robots.txt。

### 当前依赖边界

为保持 Fuwari 兼容性，当前采用 Astro 5.18.2，依赖已更新到兼容范围内的新版本；所有 Sharp 图片处理依赖统一锁到 0.35.5，包含 AVIF 图片处理修复。依赖审计仍会报告部分上游版本警告，不能将当前项目描述为“审计零漏洞”。正式部署只包含静态 HTML、CSS、JS 和图片，没有 Astro 服务端或公开图片处理接口；本地预览只监听 127.0.0.1。以后如需接收第三方上传、处理不可信内容或启用 SSR，应先升级到受支持且完成相应修复的 Astro 主版本，并重新验证主题兼容性。
